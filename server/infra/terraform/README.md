# Terraform: Cloud Run deployment

This stack deploys the control-plane server on Google Cloud with:

- **Cloud Run** service
- **Cloud SQL for PostgreSQL 18**
- **Artifact Registry** Docker repository (`control-plane`)
- **Secret Manager** for runtime sensitive configuration
- Required API enablement + IAM bindings

## Files

- `versions.tf`: Terraform / provider / backend requirements
- `variables.tf`: CI-fed inputs only
- `main.tf`: infrastructure resources
- `outputs.tf`: useful outputs

## Variables (CI-fed)

Terraform variables are intentionally minimal. If a value is not fed by CI, it is hardcoded in `main.tf` with PoC defaults.

- `project_id` (required)
- `region` (default `us-central1`)
- `container_image` (set by CI after Docker build)
- `base_url` (default `https://example.invalid`)
- `github_client_id` (optional)
- `github_client_secret` (optional, sensitive)
- `github_app_id` (optional)
- `github_app_slug` (optional, default `ghapp-demo-app`)
- `github_app_private_key` (optional, sensitive)
- `app_secrets_version` (optional, default `1`)

## Backend

This stack uses a **GCS backend**:

```hcl
backend "gcs" {}
```

Initialize with backend config:

```sh
terraform -chdir=server/infra/terraform init \
  -backend-config="bucket=<TF_STATE_BUCKET>" \
  -backend-config="prefix=control-plane"
```

## CI bootstrap values

The deploy workflow expects these **repository variables**:

- `GCP_PROJECT_ID`
- `GCP_REGION`
- `TF_STATE_BUCKET`
- `GCP_WIF_PROVIDER`
- `GCP_WIF_SERVICE_ACCOUNT`

And these optional integration values:

- Repository variables:
  - `CONTROL_PLANE_BASE_URL`
  - `CONTROL_PLANE_GITHUB_CLIENT_ID`
  - `CONTROL_PLANE_GITHUB_APP_ID`
  - `CONTROL_PLANE_GITHUB_APP_SLUG`
  - `CONTROL_PLANE_APP_SECRETS_VERSION`
- Repository secrets:
  - `CONTROL_PLANE_GITHUB_CLIENT_SECRET`
  - `CONTROL_PLANE_GITHUB_APP_PRIVATE_KEY`

## Notes

- `DATABASE_URL` is generated by Terraform, stored in Secret Manager, and injected into Cloud Run via secret reference.
- `TOKEN_ENCRYPTION_KEY` is autogenerated by Terraform from an ephemeral 32-char random value and stored as **base64** (so the app decodes it to exactly 32 bytes), then injected into Cloud Run via secret reference. It is written using a write-only attribute so it never appears in Terraform state. Bump `local.token_encryption_key_version` in `main.tf` to rotate it.
- `app_secrets_version` is also written as an annotation on the Cloud Run service template. This means bumping `CONTROL_PLANE_APP_SECRETS_VERSION` both writes new Secret Manager versions for sensitive vars **and** forces a new Cloud Run revision in the same apply, so the running service always picks up the latest secrets.
- `GITHUB_CLIENT_SECRET` and `GITHUB_APP_PRIVATE_KEY` are stored in Secret Manager (only when provided) and injected via secret refs.
- `GITHUB_APP_SLUG` is non-sensitive and injected as a regular env var; server derives install/settings URLs from it.
- Cloud Run is public (`allUsers` invoker) for this PoC.
- Cloud Run scales `min=0`, `max=1` to keep cost low.
- Cloud SQL runs PostgreSQL 18 Enterprise tier `db-custom-1-3840` (PoC-friendly).
- Cloud SQL IAM auth is enabled.
- Cloud SQL Data API is enabled (`ALLOW_DATA_API`) for Cloud SQL Studio/executeSql.
- Terraform provisions human IAM DB access from `local.iam_db_login_user_emails` in `main.tf`.
  - each email gets `roles/cloudsql.client`, `roles/cloudsql.instanceUser`, `roles/cloudsql.studioUser`
  - each email is provisioned as Cloud SQL `CLOUD_IAM_USER` on the instance
- Database read permissions are managed through DB role `ghapp_readonly` (migration `0002_readonly_access.sql`).
  - add users to that DB role with: `GRANT ghapp_readonly TO "user@example.com";`
