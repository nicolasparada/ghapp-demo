# Terraform: Cloud Run deployment

This Terraform stack deploys the control-plane server on Google Cloud with:

- **Cloud Run** service
- **Cloud SQL for PostgreSQL** (managed Postgres)
- **Artifact Registry** Docker repository
- **Secret Manager** for runtime sensitive configuration
- Required API enablement + IAM bindings (including Cloud Resource Manager bootstrap)

## Files

- `versions.tf`: Terraform / provider / backend requirements
- `variables.tf`: inputs
- `main.tf`: infrastructure resources
- `outputs.tf`: useful outputs

## Inputs

### Required

- `project_id`

### Optional (recommended once GitHub integration is configured)

- `github_client_id`
- `github_client_secret`
- `github_app_id`
- `github_app_install_url`
- `github_app_private_key`
- `github_app_webhook_secret`

Most other variables have defaults.
Notably:
- Cloud SQL password is generated by Terraform and stored in Secret Manager.
- Sensitive app config (`GITHUB_CLIENT_SECRET`, `GITHUB_APP_PRIVATE_KEY`, `GITHUB_APP_WEBHOOK_SECRET`) is persisted in Secret Manager and injected into Cloud Run via secret references (not plain env values) **only when provided**.

See `terraform.tfvars.example` for a complete example.

## Backend

This stack uses a **GCS backend**:

```hcl
backend "gcs" {}
```

Initialize with backend config:

```sh
terraform -chdir=server/infra/terraform init \
  -backend-config="bucket=<TF_STATE_BUCKET>" \
  -backend-config="prefix=control-plane"
```

## Deploy manually

```sh
# 1) create repo (first run convenience)
terraform -chdir=server/infra/terraform apply -auto-approve \
  -target=google_artifact_registry_repository.server \
  -var="project_id=<PROJECT_ID>" \
  -var="region=<REGION>" \
  ...

# 2) build + push image to Artifact Registry
#    <REGION>-docker.pkg.dev/<PROJECT_ID>/control-plane/control-plane-server:<TAG>

# 3) full apply with image
terraform -chdir=server/infra/terraform apply -auto-approve \
  -var="project_id=<PROJECT_ID>" \
  -var="region=<REGION>" \
  -var="container_image=<IMAGE_URI>" \
  ...
```

## Bootstrap values needed by CI

The GitHub deploy workflow requires these GCP values as **repository variables**:

- `GCP_PROJECT_ID`
- `GCP_REGION`
- `TF_STATE_BUCKET`
- `GCP_WIF_PROVIDER`
- `GCP_WIF_SERVICE_ACCOUNT`

For this repository, configure WIF binding against GitHub repo `nicolasparada/ghapp-demo`.
See `server/README.md` section **Deploy to Google Cloud Run with Terraform (CI)** for a complete step-by-step `gcloud` bootstrap guide, including which values are variables vs secrets.

## Notes

- `DATABASE_URL` is generated by Terraform, persisted in Secret Manager, and injected into Cloud Run from secret reference.
- `GITHUB_CLIENT_SECRET`, `GITHUB_APP_PRIVATE_KEY`, and `GITHUB_APP_WEBHOOK_SECRET` are stored in Secret Manager via write-only secret versions and injected into Cloud Run as secret refs.
- `GITHUB_APP_INSTALL_URL` is non-sensitive and injected as a regular Cloud Run environment variable.
- Cloud Run is configured with public ingress and optional unauthenticated invoker access (enabled by default).
- Cloud SQL IAM auth is enabled and a `CLOUD_IAM_USER` is provisioned for `iam_db_login_user_email`.
- Project-level IAM grants for that human user are controlled by `grant_human_db_project_roles` (default `false` for easier bootstrap permissions).
- If `base_url` is not yet known, bootstrap with the default placeholder and then update `base_url` after first deploy once Cloud Run URL is known.
